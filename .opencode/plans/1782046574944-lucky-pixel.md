# Plan — Public IR Arena Benchmark

Show aggregated winner picks as a public, methodologically honest benchmark, and widen the data model so future drilldowns can show full structured outputs per arm.

## Current state (verified)

- **Votes ARE persisted** in `run_votes` (Neon Postgres) on every "Save pick": `winner_slug`, `winner_label`, `blinded_at_vote`, `case_id`, `reasoning`, and a per-arm `models` JSONB snapshot. - **Snapshot is partial.** `VoteModelSnapshot` (`lib/votes.ts:10-21`) drops `alternativePlan`, `rationale`, `redFlags[]` from the full `TriageResult` (`lib/schema.ts:23-54`).
- **No chart library.** All visualization is hand-rolled `motion.div` (e.g. `components/run/model-card.tsx:429-460`). The aesthetic is light editorial: white cards, `#EEEDEC` hairlines, zero shadows, Newsreader serif display, Inter UI, Geist Mono `tabular-nums` for all numbers, mustard `#F4C406` used only as a signal.

## What we're building (user-confirmed)

1. **Global leaderboard** at `/benchmark` — one ranked table per model: wins, appearances, win-rate %, Wilson 95% CI, avg confidence, avg latency, blinded-vs-reveal split.
2. **Public** page + public unauthenticated GET endpoint returning aggregate stats only (no user IDs, no raw case text).
3. **Wilson 95% CI** on the win rate (rigorous, honest about sample size).
4. **Widen the snapshot AND add a separate full-output table** (`run_arms`) so future drilldowns can show rationale/redFlags/alternativePlan.

## Database schema (`db/schema.sql` append)

```sql
-- Full structured triage output per arm, normalized (one row per arm per run).
-- Source of truth for future drilldowns (rationale/redFlags/alternativePlan).
-- The run_votes.models JSONB snapshot stays as a denormalized convenience for
-- the v1 leaderboard; this table is the canonical wide record going forward.
CREATE TABLE IF NOT EXISTS run_arms (
  id              BIGSERIAL PRIMARY KEY,
  run_vote_id     BIGINT NOT NULL REFERENCES run_votes(id) ON DELETE CASCADE,
  run_uuid        TEXT NOT NULL,                      -- denormalized for fast lookups without a join
  user_id         TEXT NOT NULL,                      -- denormalized; matches run_votes.user_id
  slug            TEXT NOT NULL,                      -- gateway slug (validated against MODEL_CATALOG at write time)
  blind_label     TEXT NOT NULL,                      -- A, B, ...
  is_winner       BOOLEAN NOT NULL DEFAULT FALSE,
  decision        TEXT,                               -- EMBOLIZATION | SURGERY | CONSERVATIVE | IMAGING_FIRST
  urgency         TEXT,                               -- IMMEDIATE | URGENT_2H | SEMI_ELECTIVE
  target_vessel   TEXT,
  embolic_agent   TEXT,
  alternative_plan TEXT,
  rationale       TEXT,
  red_flags       JSONB,                              -- array of strings (max 4 per schema)
  confidence      INTEGER,                            -- 0-100
  latency_ms      INTEGER,
  status          TEXT NOT NULL DEFAULT 'finished',   -- finished | error | pending
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS run_arms_run_vote_idx ON run_arms(run_vote_id);
CREATE INDEX IF NOT EXISTS run_arms_slug_idx ON run_arms(slug);
CREATE INDEX IF NOT EXISTS run_arms_winner_idx ON run_arms(slug) WHERE is_winner = TRUE;

-- Speeds up the leaderboard's per-case drilldown (future) and per-case counts.
CREATE INDEX IF NOT EXISTS run_votes_case_id_idx ON run_votes(case_id);
```

**Migration notes:** All `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS` — idempotent, safe to re-run. Apply via `psql "$DATABASE_URL" -f db/schema.sql` or Neon MCP. Existing `run_votes` rows will NOT have the three new fields in their JSONB; the v1 leaderboard only reads `winner_slug` (already present), so this is fine. The `run_arms` table starts empty and populates from new votes only.

## Write path — atomic upsert + arm inserts

`app/api/votes/route.ts` POST handler: replace the current single-statement upsert (lines 58-78) with a single CTE that upserts `run_votes` and then inserts `run_arms` rows in one round-trip. The Neon serverless HTTP driver executes a single tagged-template string as one statement; a CTE keeps it atomic.

```sql
WITH upserted AS (
  INSERT INTO run_votes (user_id, run_uuid, case_id, case_text, reasoning,
                         blinded_at_vote, winner_slug, winner_label, models)
  VALUES ($1, $2, $3, $4, $5, $6, $7, $8, $9::jsonb)
  ON CONFLICT (user_id, run_uuid) DO UPDATE SET
    case_id = EXCLUDED.case_id, case_text = EXCLUDED.case_text,
    reasoning = EXCLUDED.reasoning, blinded_at_vote = EXCLUDED.blinded_at_vote,
    winner_slug = EXCLUDED.winner_slug, winner_label = EXCLUDED.winner_label,
    models = EXCLUDED.models, updated_at = NOW()
  RETURNING id
),
-- Wipe prior arms for this run so re-saving a run fully replaces the arm rows.
cleared AS (
  DELETE FROM run_arms WHERE run_vote_id = (SELECT id FROM upserted)
)
INSERT INTO run_arms (run_vote_id, run_uuid, user_id, slug, blind_label, is_winner,
                      decision, urgency, target_vessel, embolic_agent,
                      alternative_plan, rationale, red_flags, confidence, latency_ms, status)
SELECT id, $2, $1, m.slug, m.blind_label,
       (m.slug = $7),                       -- is_winner iff slug = winner_slug
       m.decision, m.urgency, m.target_vessel, m.embolic_agent,
       m.alternative_plan, m.rationale,
       m.red_flags::jsonb,
       m.confidence, m.latency_ms, m.status
FROM upserted, jsonb_array_elements($9::jsonb) AS m(value),
     LATERAL (
       SELECT
         m.value->>'slug' AS slug,
         m.value->>'blind_label' AS blind_label,
         m.value->>'decision' AS decision,
         m.value->>'urgency' AS urgency,
         m.value->>'target_vessel' AS target_vessel,
         m.value->>'embolic_agent' AS embolic_agent,
         m.value->>'alternative_plan' AS alternative_plan,
         m.value->>'rationale' AS rationale,
         m.value->>'red_flags' AS red_flags,
         (m.value->>'confidence')::int AS confidence,
         (m.value->>'latency_ms')::int AS latency_ms,
         m.value->>'status' AS status
     ) AS parsed
RETURNING id;
```

(Exact SQL to be finalized at implementation time — the LATERAL flatten over `jsonb_array_elements` is the cleanest way to unpack the models JSONB into one row per arm inside the same CTE. The `cleared` CTE handles re-saves on the same `run_uuid`.)

## Read path — public `GET /api/leaderboard`

`app/api/leaderboard/route.ts`:

- `export const runtime = 'nodejs'` and `export const dynamic = 'force-dynamic'` (or rely on `next: { revalidate }` from the caller).
- **No auth check.** No `verifyFreshSession()`. This is the one unauthenticated data route.
- Aggregation query (single SQL statement, grouped by `winner_slug` for wins and by `slug` from `run_arms` for appearances):

```sql
WITH wins AS (
  SELECT winner_slug AS slug, COUNT(*) AS wins,
         COUNT(*) FILTER (WHERE blinded_at_vote) AS blinded_wins,
         COUNT(*) FILTER (WHERE NOT blinded_at_vote) AS revealed_wins
  FROM run_votes
  GROUP BY winner_slug
),
appearances AS (
  SELECT slug, COUNT(DISTINCT run_uuid) AS appearances,
         AVG(confidence) FILTER (WHERE is_winner AND confidence IS NOT NULL) AS avg_winner_confidence,
         AVG(latency_ms) FILTER (WHERE is_winner AND latency_ms IS NOT NULL) AS avg_winner_latency_ms
  FROM run_arms
  GROUP BY slug
)
SELECT
  COALESCE(w.slug, a.slug) AS slug,
  COALESCE(w.wins, 0) AS wins,
  COALESCE(a.appearances, 0) AS appearances,
  COALESCE(w.blinded_wins, 0) AS blinded_wins,
  COALESCE(w.revealed_wins, 0) AS revealed_wins,
  a.avg_winner_confidence,
  a.avg_winner_latency_ms
FROM wins w FULL OUTER JOIN appearances a ON w.slug = a.slug;
```

- Join the result against `MODEL_CATALOG` in TypeScript to attach `label`, `provider`, `dotColor` (and to filter out any slugs no longer in the catalog — see Risks).
- Compute Wilson 95% CI in TS via `wilsonInterval(wins, appearances)` from `lib/leaderboard.ts`.

## Wilson 95% CI (`lib/leaderboard.ts`)

```ts
export function wilsonInterval(wins: number, n: number, z = 1.959964): { ciLow: number; ciHigh: number } {
  if (n <= 0) return { ciLow: 0, ciHigh: 0 };
  const p = wins / n;
  const z2 = z * z;
  const denom = 1 + z2 / n;
  const center = (p + z2 / (2 * n)) / denom;
  const spread = (z * Math.sqrt((p * (1 - p)) / n + z2 / (4 * n * n))) / denom;
  return { ciLow: clamp01(center - spread), ciHigh: clamp01(center + spread) };
}
```

- `n=0` → `{0, 0}` (no crash, no NaN)

## Risks & edge cases

- **Neon HTTP driver + transactions.** The CTE approach keeps the upsert + arm insert atomic over a single HTTP statement. If a multi-statement transaction were ever needed, Neon serverless supports `neonTransaction()` — but we don't need it here.
- **Catalog drift.** A model removed from `MODEL_CATALOG` (e.g. a future deprecation) would still have historical wins in `run_votes` / `run_arms`. The leaderboard mapper skips rows whose slug isn't in the catalog (so the page never renders an unknown label). The wins still count toward `totalRuns`/`totalVoters` but don't show as a row. Document this in `lib/leaderboard.ts`.
- **Zero votes.** `GET /api/leaderboard` returns `{ models: [], totalRuns: 0, totalVoters: 0, generatedAt: ... }`; the page renders the empty state. No 404, no error.
- **One vote.** One row with `appearances=1, wins=1, winRate=1, ciLow≈0.21, ciHigh=1` (Wilson on n=1). Row is flagged `low sample` (n<5).
- **Re-saving a run.** `ON CONFLICT (user_id, run_uuid) DO UPDATE` updates the vote; the `cleared` CTE wipes prior `run_arms` rows for that `run_vote_id` before re-inserting. No duplicate arm rows.
- **Public data leakage.** The aggregation query never selects `user_id` or `case_text`. Response shape is vetted to contain only `slug`, counts, averages. The cache is `public` — appropriate for aggregate stats only.
- **Performance.** With `run_arms_winner_idx` (partial index on `slug WHERE is_winner`) and `run_votes_winner_idx` (existing), the aggregation is two indexed scans + a hash. Fine for thousands of votes. If volume grows, add a materialized view refreshed by a cron — out of scope here.
- **Substituted models.** `gemma-4-31b` carries a `footnote` (`lib/models.ts:84-88`). The leaderboard row shows a small `*` next to the label with the footnote in a tooltip (reuse the existing `<TooltipProvider>` from `app/layout.tsx`).
